# Style Guide — Final

## Typography

### Font
- Primary font: **Inter**

### Hierarchy
- `H1`: large hero headline, premium but readable
- `H2`: section headline
- `H3`: module headline
- `H4`: compact subheading / module intro

### Type rules
- Main paragraph text is **black**.
- H1 and H2 need slight additional breathing room versus earlier tighter versions.
- Labels / micro-headings should be uppercase, compact, and blue when used as module or section identifiers.
- Do not use weak pale gray for core reading text.

## CTA rules

### Primary CTA
- Always `#447ACB`
- White text
- 6px radius
- Used for the main action in hero, footer, bands, and modules

### Secondary CTA on light surfaces
- Black fill
- White text
- 6px radius

### Secondary CTA on dark surfaces
- White outline
- Transparent background
- White text

## Pills / metadata
- Use rounded pills
- Use flat UI colors from the approved palette
- Avoid squared editorial tags that read as stiff or awkward

## Surfaces
- Light-first reading surfaces dominate the site
- White cards / modules are primary
- Soft steel wash is used for subtle separation
- Risk cards use light red wash
- Dark bands are used strategically for proof, CTA, outcomes, or compressed emphasis

## Contrast band rules
- Dark bands should use the approved blue-gray dark range
- Small section/module labels inside dark bands should stay blue where appropriate
- Callout numbers on dark bands should be blue
- Supporting copy on dark bands should be white or near-white

## Content rules
- Prefer bullets over long explanatory blocks inside modules
- Keep proof modules concrete and scannable
- Avoid decorative filler content
- Use real artifacts where available

## Snapshot rules
- Snapshot top-of-page should frame the case clearly
- Use a mix of factual labels and numeric callouts
- Avoid giant box grids with repetitive text

## Timeline rules
- Delivery rail: **one bullet per phase only**
- Narrative vertical timeline: bubble sits directly on the line
- Use timelines to clarify sequence, not decorate the page

## Proof rules
- Dark quote card spans full width when used as hero proof
- Supporting proof cards can sit below in lighter modules
- Metric callout should break onto its own line above the support label

## Artifact rules
- Architecture diagrams should feel like simplified consulting visuals
- Annotated screenshots should use only a few sharp callouts
- Avoid engineering-whiteboard clutter and fake product-dashboard treatments
