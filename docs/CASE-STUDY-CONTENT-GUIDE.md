## 2. IMAGE & MEDIA SPECIFICATIONS

### IMAGE A — Hero Image
| Property | Spec |
|---|---|
| Block name | `hero.image` |
| Display height | Fixed **582px** across ALL screen sizes |
| Display width | Full viewport width (mobile/tablet) · Full container on desktop |
| Rendering | **Grayscale filter applied automatically** — supply a color photo |
| Crop behavior | Centered horizontally, top-anchored |
| Recommended file size | **1440 × 582px minimum** · 2880 × 1164px @2x preferred |
| Format | JPG or PNG |
| Content guidance | Full-bleed product screenshot, dashboard view, or environmental photo. Should work cropped to a wide strip. Faces, screens, and environments all work. |

> **Critical note:** This image renders in grayscale. Make sure it has strong contrast and readable detail even without color. Avoid images that rely on color to convey meaning.

---

### IMAGE B — Problem Statement Media
| Property | Spec |
|---|---|
| Block name | `problem.media` |
| Aspect ratio | **16:9** |
| Mobile width | ~327px → height ~184px |
| Tablet width | ~672px → height ~378px |
| Desktop width | **620px → height 349px** |
| Recommended file size | **1240 × 698px** (2x for desktop) |
| Format | JPG, PNG, or GIF |
| Position on page | Left column of Problem Statement section, inside white panel |
| Content guidance | A before-state screenshot, research artifact, user journey map, whiteboard photo, or diagram showing the problem. Should be readable at 620px wide. |

---

### IMAGE C — Recognition Featured Media
| Property | Spec |
|---|---|
| Block name | `recognition.featured.media` |
| Aspect ratio | **16:9** |
| Mobile width | Full container width |
| Desktop width | **530px → height 298px** |
| Extra-large (1280px+) | **530px → height 298px** (fixed) |
| Recommended file size | **1060 × 596px** (2x) |
| Format | JPG or PNG |
| Position on page | Top of Recognition section, left column |
| Content guidance | Award certificate scan, press screenshot, product launch photo, event photo, or final deliverable. |

---

### DESIGN C — Solution Cards (No images needed)
| Property | Spec |
|---|---|
| Block name | `solution.cards` (3 cards) |
| Aspect ratio | **9:16** (portrait) |
| Desktop card width | ~448px · height ~797px |
| Art | **CSS-generated** — no image files needed |
| Available art styles | `"olive"` (warm green gradient) · `"ux"` (red/purple) · `"motion"` (teal/navy) |
| Content per card | Category label · Read time · Title (1 sentence) |

## 3. SECTION-BY-SECTION CONTENT GUIDE FOR AI

Use this when writing copy. For each case study, fill in every field below.

---

### SECTION 1 — HERO

**`hero.title`** — Project title
- Format: `[Client Name]: [Short Project Description]`
- Length: 5–10 words
- Examples: "CPS Energy: Smart Streetlight & Smart City Operations" · "Solstice Ops: Field Service Visibility Platform"

**`hero.intro`** — Intro paragraph (appears right of title on desktop)
- Length: 2–4 sentences, 40–80 words
- Tone: Direct, outcome-focused. Lead with the problem or the stakes, not your title.
- Do NOT start with "I" or a job title description.

**`hero.primaryCta`** — Primary button
- Label: Short action phrase ("View Live Product" · "Read Case Study" · "Book a Call")
- href: URL to the live product, Figma prototype, or booking link

**`hero.secondaryCta`** — Secondary button
- Label: Typically "View CV" or "See More Work"

**`hero.image`** — Hero image
- src: File path under `/public/`
- alt: Descriptive alt text (for accessibility)

---

### SECTION 2 — AT-A-GLANCE

**`atAGlance.eyebrow`** — Small label above section
- Standard value: `"At-a-glance"`

**`atAGlance.title`** — Section headline
- Length: 3–7 words
- Should name the capability or outcome area (e.g. "Service Operations Performance")

**`atAGlance.copy`** — Supporting paragraph
- Length: 2–4 sentences, 30–60 words
- Summarizes what was achieved at a high level

**`atAGlance.stats`** — 4 stat cards
Each stat has:
- `value`: Number only (e.g. `"2.4"` · `"87"`)
- `suffix`: Unit (e.g. `"x"` · `"%"` · `"K"`)
- `label`: 3–6 word description (e.g. `"Faster field reports"`)

---

### SECTION 2B — PROBLEM STATEMENT

**`problem.eyebrow`** — Standard value: `"Problem Statement"`

**`problem.title`** — Headline
- Length: 4–8 words
- Names the core challenge (e.g. "Invisible Field Operations Hurt Service Delivery")

**`problem.media`** — Image or video
- `kind`: `"image"` or `"video-placeholder"`
- `src` (if image): file path
- `title` (if video): short title shown on placeholder
- `subtitle` (if video): URL or instruction note
- `aspectRatio`: `"16/9"`

**`problem.overview`** — Main problem description
- Length: 3–6 sentences, 60–120 words
- Describes the situation, the gap, and why it mattered

**`problem.projectOverviewRows`** — Metadata rows (3–5 rows)
Each row: `label` + `value`
- Standard labels: Project · Client · Industry · Location · Timeline · Team Size

**`problem.tools`** — Tool icons
Each: `label` (full name) · `icon` (path to SVG file under `/public/tool-icons/`)
- Pre-built icons available: `/tool-icons/figma.svg` · `/tool-icons/illustrator.svg` · `/tool-icons/photoshop.svg` · `/tool-icons/adobe-xd.svg` · `/tool-icons/after-effects.svg`
- To add a new tool: save a 36×36px SVG to `/public/tool-icons/[tool-name].svg` and reference it by path

**`problem.quote`** — Pull quote
- `quote`: 1–3 sentences from a stakeholder, team member, or your own articulation of the challenge. First-person or attributed is fine.
- `attributionTitle`: Speaker name or "Challenge Quote"
- `attributionSubtitle`: Speaker title or "Replace with speaker name and title"

---

### SECTION 2C — MY ROLE

**`role.eyebrow`** — Standard value: `"My Role"`

**`role.title`** — What you did
- Examples: "Lead Product Designer" · "UX Strategy & Systems Design" · "End-to-End Design Lead"

**`role.copy`** — 1–3 sentences describing your scope
- Keep focused on what YOU did, not the project generally

**`role.tags`** — 3–5 discipline tags
- Examples: "Research" · "Systems Design" · "Prototyping" · "Stakeholder Facilitation" · "Design Leadership"

**`role.stats`** — 4 stat cards (same format as atAGlance.stats)
- These must reflect **ownership and scope**, NOT outcomes or results
- Outcomes belong in the Impact section — do not repeat them here
- **Preferred metrics (in priority order):**
  1. **Team size** — total headcount on the program (e.g. `"15"`, label: `"Team size"`)
  2. **Budget** — program or project budget (e.g. `"$2"` + suffix `"M"`, label: `"Program budget"`)
  3. **System integrations** — number of platforms/tools/systems integrated or scoped (e.g. `"6"`, label: `"System integrations"`)
  4. **Timeline** — program duration in months (e.g. `"8"` + suffix `" mo"`, label: `"Program timeline"`)
- **Substitutions if data is unavailable:**
  - If budget is unknown → use **stakeholder orgs aligned** (e.g. `"3"`, label: `"Stakeholder orgs"`)
  - If team size is unknown → use **workstreams led**
  - If system integrations is unknown → use **product surfaces owned**
- **Never use** percentage improvements, user growth, or any metric that belongs in Impact

**`role.narrative.title`** — Section sub-headline inside narrative block
- 5–10 words · sets up the story

**`role.narrative.paragraphs`** — Array of body paragraphs
- 2–4 paragraphs, 50–100 words each
- Tells the story of how you approached the problem

**`role.narrative.highlights`** — Optional bullet points (pipe-styled)
- 2–4 items, 1 sentence each
- Key decisions, turning points, or specific contributions

**`role.narrative.closing`** — Optional closing paragraph
- 1–3 sentences wrapping up the role narrative

---

### SECTION 3 — SOLUTION

**`solution.eyebrow`** — Standard value: `"Solution"`

**`solution.title`** — Headline describing what you built
- Length: 5–10 words
- Should name the solution approach (e.g. "A Unified Field Operations Platform Built for Speed")

**`solution.copy`** — 2–3 sentence summary of the solution
- 30–60 words

**`solution.cards`** — 3 cards, each with:
- `category`: Discipline label (e.g. "Systems Design" · "Research" · "Prototyping")
- `readTime`: Format as "X min read"
- `title`: 1 sentence describing the specific solution approach (8–15 words)
- `art`: `"olive"` · `"ux"` · or default (any other value)

---

### SECTION 3B — SUPPLEMENTAL NARRATIVE

**`supplementalNarrative.title`** — Section headline
- Continues the solution story or digs into a specific challenge

**`supplementalNarrative.paragraphs`** — 1–3 paragraphs
**`supplementalNarrative.highlights`** — Optional pipe bullets
**`supplementalNarrative.closing`** — Optional closing paragraph

---

### SECTION 4 — IMPACT

**`impact.eyebrow`** — Standard value: `"Impact"`

**`impact.title`** — Outcome headline
- Examples: "The Results I Drove" · "Measurable Outcomes" · "What Changed"

**`impact.intro`** — 1–2 sentence framing of results
- 20–40 words

**`impact.proofPoints`** — 3 short labels (shown as tags with arrows between them)
- 2–4 words each · directional · Examples: "Faster decisions" · "Lower friction" · "Better retention"

**`impact.stats`** — 4 stat cards (same format as before)
- These should be the strongest, most specific metrics from the project

**`impact.beforeAfter`** — Comparison table
- `title`: "Before & After" or a specific framing
- `summary`: 1–2 sentences contextualizing the comparison
- `columns`: Two columns, each with `label` ("Before"/"After") · `title` (short phrase) · `points` (3–4 bullet strings)

**`impact.journeySteps`** — 3 numbered steps (shown with a vertical dotted connector)
Each step: `step` (number as string) · `title` (4–8 words) · `copy` (2–4 sentences)
- These represent phases of the user's transformation or the product's evolution

---

### SECTION 5 — DELIVERY

**`delivery.eyebrow`** — Standard value: `"Implementation"` or `"Delivery"`

**`delivery.title`** — E.g. "Delivery Phases" · "How We Built It"

**`delivery.introTitle`** — Sub-headline
**`delivery.introCopy`** — 2–4 sentences about the process

**`delivery.phases`** — Array of phase objects (3–6 phases typical)
Each phase:
- `phase`: "Phase 01" · "Phase 02" etc.
- `title`: 1–2 word phase name (e.g. "Discover" · "Define" · "Design" · "Test" · "Launch")
- `copy`: 1 sentence describing what happened in this phase
- `ringClass`: Tailwind border color class (e.g. `"border-[#D39D23]"`)
- `labelClass`: Matching text color class (e.g. `"text-[#D39D23]"`)

---

### SECTION 6 — CHALLENGE QUOTE (dark section)

**`challengeQuote.quote`** — Full quote text (no quotation marks — template adds them)
- 1–3 sentences
- Can be from a stakeholder, executive, user, or your own articulation of a key insight

**`challengeQuote.attributionTitle`** — Speaker name
**`challengeQuote.attributionSubtitle`** — Speaker title / company / context

---

### SECTION 7 — RECOGNITION

**`recognition.eyebrow`** — Standard value: `"Recognition"`

**`recognition.title`** — E.g. "Press & Accolades" · "Awards & Recognition"

**`recognition.intro`** — 2–4 sentences introducing the recognition
- Tone: Confident but not boastful. Connects outcomes to broader impact.

**`recognition.featured`** — The primary/most prominent recognition item
- `media`: Image or video-placeholder (same format as problem.media)
- `company`: Organization name + location
- `dates`: Date range (e.g. "March 2023 – Present")
- `summary`: 1–2 sentences describing the recognition
- `tags`: 2–3 category tags

**`recognition.rows`** — Additional recognition items (no image)
Each row: `company` · `dates` · `summary` · `tags[]`

## 4. CONTENT RULES & VOICE GUIDELINES

### Tone
- **Direct and confident** — state outcomes, not effort
- **Specific over vague** — "2.4x faster field reports" not "significantly improved reporting"
- **First person where appropriate** — "I led" not "the team led" (this is a personal portfolio)
- **No fluff** — do not use filler phrases like "leveraging synergies," "passionate about," "dynamic solutions"

### Numbers
- Always use real metrics where available
- If approximated, round to meaningful precision (87%, not 86.7%)
- Stat suffixes: use `x` for multipliers, `%` for percentages, `K`/`M` for large counts

### Length constraints
| Field | Target length |
|---|---|
| H1 (hero title) | 5–10 words |
| Intro paragraph | 40–80 words |
| Pull quote | 25–60 words |
| Stat label | 3–6 words |
| Phase copy | 8–16 words (1 sentence) |
| Body paragraphs | 50–120 words each |
| Before/After bullet | 8–18 words |

## 7. DATA FILE LOCATION

Each case study is a TypeScript file in:
```
/src/content/case-studies/[slug].ts
```

The file exports a single object that matches the `CaseStudyData` type. See `cps-energy.ts` or `solstice-ops.ts` as reference examples.

The page route is created at:
```
/src/app/[slug]/page.tsx
```
