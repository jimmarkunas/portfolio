# Locked Brief — Final

## Core direction

Build a portfolio and case-study system that feels like:
- **BCG** for credibility
- **Apple** for premium restraint and overall design quality
- **Kane Sherwell** for premium editorial rhythm
- **Shippit / Rollas case-study style** for clean, modern case-study presentation

This is **not** a SaaS dashboard UI.
This is **not** a generic template portfolio.
This is **not** decorative design for its own sake.

The site should communicate:
> This guy looks like someone who can lead my project and fix all of my problems.

## Audience

Mixed audience:
- recruiters
- hiring managers
- consulting clients
- agency leaders
- enterprise stakeholders

## Design character

The system should feel:
- light-first
- premium
- editorial
- sharper-edged
- modern
- restrained
- masculine through contrast, clarity, and structure
- visibly designed, but not gimmicky

## Explicit rejections

Avoid:
- generic dashboard aesthetics
- fake charts used as decoration
- decorative blobs or abstract startup visuals
- cute or playful UI language
- weak hierarchy
- over-dense throwaway interface boxes
- soft “friendly startup” card styling as the dominant tone
- washed-out gray text replacing real reading contrast

## Information priorities

The system must prioritize:
- business outcomes
- project scope
- timelines and phases
- architecture and integrations
- stakeholder / vendor / dependency complexity
- before / after transformation
- process / workflow when helpful
- risks and blockers
- delivery ownership
- proof and real artifacts

## Charts

Charts are allowed **sparingly** and only when they communicate real information.
Default to diagrams, proof cards, timelines, callouts, screenshots, and architecture artifacts instead.

## Structural rules

- Same base case-study skeleton across all case studies.
- Same overall page rhythm across all case studies.
- Module mix can vary by story.
- Architecture / integration artifact should appear on every case study when available.
- Timeline should appear on every case study.
- Before / after should appear on every case study.
- Annotated screenshot / artifact should appear on every case study when available.
- KPI / proof strip should appear on every case study.
- Quote / testimonial appears when available.

## Density

Target density is:
- medium density
- serious
- premium
- not sparse
- not dashboard-busy

## Button rules

- Primary CTA is **always blue**.
- Secondary CTA on light surfaces is **black fill / white text**.
- Secondary CTA on dark surfaces is **white outline**.
- Button radius is **6px**.

## Content rules

- Prefer bullets over dense text blocks inside modules.
- Callout numbers on dark modules stay blue.
- Supporting text on dark callouts stays white.
- Keep labels literal and recruiter-readable.

## Color confirmations

- Primary blue: `#447ACB`
- Teal: `#1E8E89`
- Amber: `#C7922A`
- Red: `#B54A3A`
- Steel blue support tone: `#5B78A5`
- Main paragraph text: black
- Light-first background system
- Dark contrast bands allowed and encouraged for proof / CTA / outcomes
